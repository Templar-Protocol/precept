Precept admin console

This page has no server and keeps no record of you. It checks everything it is about to sign against pinned data, shows you exactly what it says, and hands the signing to Freighter. It talks to the public Stellar RPC (reads, simulation and, when you press the button, submit) and, on the mobile path, the WalletConnect relay. The only thing it stores is a WalletConnect session while the mobile path is open, and it deletes that when the request finishes.

Three things to check before you approve.
  1. This message came from the known proposer, on a channel you have already authenticated. A link plus a matching payload only proves the link and the message agree — not who sent them.
  2. The action below is what you expected (and what that message says). Read the contract, the function and every argument.
  3. In Freighter, tap __check_auth to expand it, then check the network, the smart account and the signature_payload against the message you received. The released Freighter apps show the payload as 32 decimal bytes ({"0":124,…,"31":238}); hex or base64 are equally fine — all 32 bytes must match.
If anything differs, stop and ask the proposer on another channel.
